Field Guide · 架构调研总览

四款主流 Agent 的
同一个内核，四种取舍

Claude Code、OpenAI Codex CLI、OpenClaw、Hermes —— 它们的差别不在"是不是 agent"，而在围绕同一个循环各自做了哪些工程取舍。这份指南把取舍摊开对照，作为自研 agent 的设计依据。

所有 agent 共享的内核

一个围绕单次模型对话的 while 循环，源自 2022 年的 ReAct。模型自己决定下一步——这正是 agent 区别于 workflow 的地方。

循环只在模型返回 end_turn（无工具调用）时终止，并由 maxSteps 兜底。填爆上下文的从来是工具输出，不是用户输入。

01

四款产品的定位与取舍

Claude Code · Anthropic

Claude Code

终端编码 agent（= Agent SDK loop + TUI）

语言
TypeScript / Node
循环
while stop_reason==tool_use 单线程
后端
主 Claude，SDK 可扩展

最锋利处：「prompt caching 是一切」——请求按稳定前缀分层；hooks/permissions 在 harness 层强制，而非靠 prompt。

Codex CLI · OpenAI

Codex CLI

终端编码 agent（Rust 核心 + TS 启动器）

语言
Rust · 单二进制
循环
Session → Task → Turn（SQ/EQ 队列）
后端
仅 Responses API，previous_response_id 传状态

最锋利处：OS 内核级 sandbox（Seatbelt / bwrap+seccomp / Win 受限令牌），sandbox 与 approval 两层正交，fail-closed。

OpenClaw · 开源

OpenClaw

本地优先的个人通用助理

语言
TypeScript / Node（pnpm）
循环
Gateway 控制面 + 嵌入式 runtime
后端
可插拔 provider/model 字符串

最锋利处：Gateway 单一类型化控制面（TypeBox 校验帧）；三层安全 sandbox / tool-policy / elevated；连 20+ 消息渠道。

Hermes · Nous Research

Hermes Agent

自托管通用 agent 运行时

语言
Python
循环
run_conversation() 同步 + 预算追踪
后端
18+ provider · 三种 wire-format

最锋利处：(provider,model) resolver + chat/responses/anthropic 三线格式——同一 loop 驱动三家。插件化 provider 与 memory。

03

给自研 agent 的启示（按优先级）

序号 = 落地优先级
1

loop 笨且单线程

stop_reason 终止 + maxSteps 兜底，别过度设计编排。

2

为前缀缓存分层请求

system+tools 在前、项目上下文居中、易变对话在后。只 append，不改前缀。

3

工具内置结果截断

分页 / 截断打标记 / 大输出溢出到文件。填爆上下文的是工具输出。

4

少而锋利的工具 + 代码执行

臃肿重叠制造模糊决策点；grep/glob/bash 廉价覆盖巨大面。

5

权限在 harness 层强制

deny→ask→allow，只读零摩擦。安全规则写进代码，不写进 prompt。

6

provider 归一化两处差异

stop_reason 命名 + tool_result 回填方式，藏进 adapter，loop 只见中立类型。

7

把工具输出当不可信

回填前中和指令形状内容；打破「私有数据 + 不可信内容 + 对外通信」致命三要素。

8

UI-agnostic 引擎 + 事件流

Op/Event 序列化流解耦前端；run 立即返回句柄。
